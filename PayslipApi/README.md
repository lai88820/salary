# 薪資明細列印 × 收費對帳系統

補習班（20 個分校、400 餘名員工）的內部作業工具，把兩項原本耗時的人工流程自動化。

| 模組 | 原本 | 現在 |
|---|---|---|
| **薪資明細列印** | 從加密 Excel 逐人抄成薪資單，400 人 | 匯入後勾選、批次產生 PDF，一人一頁 |
| **收費對帳** | 3 分校 × 5 種收費項目、800+ 筆紙本與系統人工核對，約 2 天 | 上傳兩個 Excel，**數秒**完成 |

收費對帳首次上線即找出 **約 NT$85,000 應退未退款項**與 30 餘筆資料登錄錯誤。

## 模組一：薪資明細列印

### 資料流

```
11508薪資計算明細.xlsx  （密碼保護、含公式）
        │  tools/轉換SQL.bat  ← 把 Excel 拖上去就好
        ▼
  excel_to_sql.py
        │  msoffcrypto 解密 → openpyxl 讀「公式」與「值」兩份
        ▼
  payroll_115-08.sql   （7 張表的 DDL + INSERT，同月份重跑會先清空）
        │  MySQL Workbench 執行
        ▼
     MySQL payroll
        │  Dapper
        ▼
  API → QuestPDF → PDF（一人一頁）
```

### 技術難點：從 Excel 公式反推應扣項目

主檔的「勞健保」是**一個合併後的數字**，但薪資單必須拆成「代扣勞保」與「代扣健保」兩列。

解法是**不看值、看公式**：

```python
# J 欄公式長得像 =-(1234+567)  →  第 1 項是勞保、第 2 項是健保
terms = split_terms(formula)          # 依括號深度拆出最外層的 +/- 項
amounts = [-sign * evaluate(t, val) for sign, t in terms]
```

只有單一項時無法從結構判斷是勞保還是健保，因此先**掃過全部有兩項以上的公式**，學出勞保基數與健保基數的集合，再回頭比對：

```python
def collect_bases(j_formulas):
    """從兩項以上的公式學習：第 1 項是勞保基數，第 2 項是健保基數"""
```

`split_terms()` 需自行處理括號平衡，不能直接用 `split('+')`，否則 `=-(a+b)*c` 會拆錯。

### 其他處理

- **帶班科目人數**：從自由格式的備註文字抽出安親／資數／輔導資數／兒美／才藝／其他的人數，且只取當月份的段落
- **離職人員**：最後上班日取代工號顯示
- **講師**：與一般員工資料結構完全不同（多筆授課明細、堂數 × 鐘點費），另一組資料表與版型

## 模組二：收費對帳

### 要解的問題

系統匯出的「應收項目明細表」記錄**收了多少錢**；各班紙本訂餐表記錄**實際吃了幾餐／有沒有參加**。兩者差額就是該退的錢，但過去只能人工逐筆核對。

### 四條主規則

| 規則 | 判斷 | 輸出 |
|---|---|---|
| R1 名單 | 兩邊互相找不到人 | 漏登記／該退未退 |
| R2 日期 | 繳費日期不一致 | 抄錄錯誤 |
| R3 金額 | 紙本收費金額 ≠ 系統已繳 | 金額寫錯 |
| R4 退費 | `已收金額 − 實際份數 × 單價 − 已退費` | 應退金額 |

**R4 刻意用金額計、而非份數計。** 用份數會在三個地方出錯：

- 點心「每週五天」收 650，不是 20 × 33 = 660，用份數反推會少退
- 有沖銷的人已繳 ≠ 應繳，用應繳的份數算會多退
- 有折扣的同理

改用金額後，這三種狀況都不需要特別處理。

### 十個實務例外

全部來自實際對帳踩到的狀況，寫在 `ReconcileEngine.cs` 對應區塊的註解裡。

| # | 狀況 | 處理 |
|---|---|---|
| 1 | 同人多筆收費（18 餐 + 加訂 1 餐） | 先依人彙總再比，否則第二筆會算出負數退費 |
| 2 | 姓名帶英文（`黃宥榛/Moana`、`阮荺茜(Molly)`） | 正規化：去掉 `/後綴`、括號、英數字 |
| 3 | **同名不同人**（同一份名單有兩位同名學生） | 優先用學號；無學號時為已知限制 |
| 4 | 沖銷金額 | 以「已繳」反推，不用「應繳」 |
| 5 | 折扣 | 同上 |
| 6 | 未付款 | 列為欠費，不計入應退 |
| 7 | 帳單待結單 | 單獨標示提醒結單 |
| 8 | 已退費 | 從應退扣掉，避免重複退款 |
| 9 | 月費上限 | 用金額計算自然涵蓋 |
| 10 | 班級登錄不一致 | 以學號為準，班級僅供顯示 |

另外**一律重算退費金額，不採信紙本的合計欄** —— 驗證月份的 11 個班級中有 6 個班的合計是錯的（表格跨頁時只加到部分列）。

### 三層防呆

配錯檔案會產出「看起來正常、實際完全錯誤」的金額，因此比對後做三重檢查：

| 層 | 條件 | 抓什麼 |
|---|---|---|
| 1 | 對得上的人 < 50% | 不同分校、不同月份 |
| 2 | 對得上的人裡，金額不符 > 50% | **分頁或收費項目選錯** |
| 3 | 分頁名稱指向其他收費項目 | 分頁叫「信義-午餐」卻選了電影 |

第 2 層是實測後補的：選錯收費項目時，因為是同一批學生，**姓名 93% 都對得上**，第 1 層完全攔不住，但金額已經全錯。

### 驗證結果

以實際月份資料比對，8 組資料集金額全數吻合人工核對結果：

| 資料集 | 人數 | 已收 | 應退 |
|---|---|---|---|
| 信義-午餐 | 204 | 348,080 | 75,525 |
| 文德-午餐 | 64 | 105,925 | 7,505 |
| 文德-點心 | 30 | 17,029 | 224 |
| 博愛-大型活動 | 65 | 102,700 | 1,580 |
| 其餘 4 組 | — | — | 0（本即無應退） |

## 執行方式

### 開發

```bash
# 後端
cd PayslipApi
dotnet restore
dotnet run                    # http://localhost:5080

# 前端
cd payslip-web
npm install
ng serve                      # http://localhost:4200
```

### 每月匯入薪資資料

把 Excel 拖到 `tools/轉換SQL.bat` 上，產生的 `.sql` 用 MySQL Workbench 整份執行。

### 打包給非技術使用者

```bash
cd PayslipApi
publish.bat
```

會依序 build Angular → 複製到 `wwwroot` → `dotnet publish --self-contained`，
產出的 `PayslipApp` 資料夾整個複製到目標電腦，雙擊 `start-payslip.bat` 即可使用，**免安裝 .NET**。
